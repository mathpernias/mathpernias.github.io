02

Selected work

Four projects from my work at iA Financial Group: context, approach, outcome.

A

Security · Azure Data Factory

No more passwords sitting in plain text in our data pipelines

Moving pipeline credentials into Azure Key Vault

  • Azure Key Vault
  • Managed identity
  • OAuth2
  • ADF

Problem

ADF pipelines called the contact-center platform's API with OAuth2 client credentials stored directly in linked-service settings, readable by anyone with access to the factory.

Approach

Migrated every credential to Azure Key Vault. Linked services now reference vault secrets resolved at runtime through the factory's identity, so nothing sensitive lives in pipeline definitions or the repo.

Outcome

No exposed secrets, no downtime during the migration, and a setup that meets the company's security standards.

B

Privacy · Snowflake

Testing on realistic data without exposing a single customer

Config-driven PII masking for test environments

  • Snowflake
  • SQL
  • Nested JSON
  • Data privacy

Problem

Developers need production-like data to test, but contact-center conversations are nested JSON full of names, emails and phone numbers. Copying them to lower environments was a privacy risk.

Approach

Built a configurable anonymisation tool that walks nested JSON and replaces personal fields. Which fields are sensitive is declared as rules, not hard-coded, so a new source needs configuration rather than new code.

Outcome

Teams test on realistic data while customer privacy stays protected.

C

FinOps · Azure

Same service, 30% cheaper: the server was never the problem

Right-sizing the integration runtime VM: −30% cost

  • Azure VMs
  • Self-hosted IR
  • ADF
  • Capacity analysis

Problem

The VM hosting our self-hosted integration runtime (SHIR) had 4 processors and 14 GiB of memory. Pipelines saw latency, and the question was whether to scale up, or whether the bottleneck was somewhere else.

Approach

Analysed memory, CPU, API queues, concurrency and HTTP 429 responses. The VM was far from saturated; latency came from request concurrency and API rate limiting. Tuned ADF concurrency and validated the new size progressively from DEV to PROD.

Outcome

Moved to a machine half the size (4 → 2 processors, 14 → 8 GiB of memory): about 30% lower cost, with the same level of service.

D

DevOps · Docs-as-code

Documentation that updates itself with the code

A docs-as-code pipeline that publishes to SharePoint

  • Azure Pipelines
  • Markdown
  • PowerShell
  • Git

Problem

Documentation for data tables lived in scattered files, drifted out of date, and people stopped trusting it.

Approach

Moved the docs into Markdown next to the data definitions, reviewed in pull requests like any other change. On merge, an Azure Pipeline publishes them to the company SharePoint.

Outcome

One source of truth that stays in sync with the code. Currently a proof of concept, ready to extend to more teams.
